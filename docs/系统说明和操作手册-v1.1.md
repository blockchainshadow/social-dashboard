# 社交平台数据看板 · 系统说明和操作手册

更新：2026-10-02。本文件持续维护；v1.0 是冻结的旧基线。实现细节见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 1. 访问与登录

| 入口 | 地址 |
|---|---|
| 主站 | https://social-dashboard-9ya.pages.dev/ |
| 备用站 | https://blockchainshadow.github.io/social-dashboard/ |
| 本地 | http://127.0.0.1:8000/ 或 `/web/` |

两站都支持经 Worker 提交 YouTube 管理任务，采集仍由本机执行。输入分配的用户名和明文密码；顶栏首位显示当前账号，点击退出撤销服务端会话。旧账号首次登录须换成不同的 12–1024 字符密码；换密前不能新增、刷新、修改或删除频道。换密后重新登录。

admin 默认自己名下频道，点击「全员」查看全部；成员管理由服务端检查归属。频道历史为公开数据，筛选不是保密控制。客户端不保存密码哈希；不要把 token 或密码粘贴到日志/聊天。

## 2. 新增、刷新和查看

1. 管理菜单 → 添加账号。YouTube 接受 `@handle`、裸 handle、主页 URL、频道 ID；配置保存后立即返回排队任务。
2. 初始快照获取档案及最近 50 条视频，先发布并可查看，再自动全量补齐；任务完成必须晚于分片和索引发布成功。API 全量分页失败会明确失败，不能把部分结果标成完整。
3. 单频道刷新会入队；本地自动启动执行器，线上等待本机 watch 接收。普通刷新对已追踪视频批量更新，并发现最近上传。
4. 选择「终身」查看所有已追踪视频；7/28/90 天筛选的是发布时间范围。未知统计显示「—」，陈旧视频标注最后有效采集时间。
5. 公网「检查发布」仅重新检查 R2 索引，不抓取 YouTube；「发布于」不是每个视频的采集时间。
6. TikTok 保留原本地采集/刷新流程，远端刷新会提示使用本地；不进入 YouTube initial/full 队列。

## 3. 本地运行

Node >= 22.14（需要 `node:sqlite`）。

```bash
node server.mjs
node server.mjs 8000
npm test
# 接收远端请求、协调配置、补采新频道并发布
node scripts/run-dashboard-jobs.mjs --reconcile --queue-new --run --sync
# 手动指定频道采集，直接写 SQLite
node scripts/fetch-youtube.mjs --only @频道handle --full
bash scripts/publish-r2.sh
```

非回环绑定必须设置 `DASH_TOKEN`；它只用于受信运维调用，不代替普通浏览器 Worker 会话。不要同时修改原始 JSON 来更新 YouTube，SQLite 才是权威历史。

## 4. 调度、锁与日志

以 `crontab -l` 为准。当前 watch 每 2 分钟、daily 每日 09:30、用量每小时 17 分。

- watch 同步 Git 配置、领取远端请求、补采新频道、逐频道发布。
- daily 排队刷新、逐频道发布，随后创建并上传加密备份；单频道失败也尝试备份权威数据库。
- Git `.git-sync-lock` 只覆盖 Git 操作；SQLite 执行器租约覆盖采集及发布；`logs/.publish-r2-lock` 单独防止并发索引发布。活 PID 永不因超过固定时长被抢占。
- 远端请求确认丢失可重放；request ID 仍关联原任务，不重复采集已完成请求。
- `logs/watch.log`、`logs/youtube-daily.log`、`logs/cron.log` 超 20MB 轮转。日志可能含运维信息，不能公开或提交 Git。

## 5. 文件与发布

| 路径 | 性质 |
|---|---|
| `data/dashboard.sqlite` 及 WAL/SHM | 权威历史与任务，600，不能删除 |
| `data/youtube-history.json` | 一次性迁移输入，运行时不再写入 |
| `data/dashboard-index.json`、`data/channels/*.json` | 可重建发布产物，不进 Git |
| `data/dashboard-jobs.json` | 裁剪后的公开任务状态，不含凭据 |
| `channels.json` | Git 权威配置，Worker 用 SHA 冲突重读更新 |
| `index.html` | 唯一页面源码 |
| `web/index.html` | `sync-static.sh` 单向生成的小文件镜像 |
| `backups/` | 本机加密备份，不进 Git |

`bash scripts/publish-r2.sh` 经 Worker R2 绑定上传，只传变更头像及频道分片，最后发布索引；`--full` 重传，`--jobs-only` 只更新完成/失败状态。任一必要上传失败都会返回非零码，成功状态不提前写入。

代码发布：修改共享浏览器模块后提升根页导入 URL 的 `?v=` 版本；修改根页面后运行 `bash scripts/sync-static.sh`，提交代码、配置和文档，`git push origin main` 触发双站构建。Worker 单独 `npm run deploy`；秘密通过 Worker secret 配置，不在 `wrangler.jsonc` 写入值。默认数据源为 R2，本地预览自己的生成物须显式 `?data=<地址>`。禁止把项目工作目录直接整体上传 Pages（其中有运行库、日志和秘密）。

## 6. 加密备份与恢复

```bash
# SQLite 一致性快照 → AES-256-GCM → R2
node scripts/backup-dashboard.mjs --backup --upload
# 下载、验密、核对清单和数据库，再恢复到空目录
node scripts/backup-dashboard.mjs --download backups/dashboard-时间戳.enc --target /path/to/empty-restore
# 使用已有本地加密文件
node scripts/backup-dashboard.mjs --restore --file backups/dashboard-时间戳.enc --target /path/to/empty-restore
```

快照使用 `VACUUM INTO`，包含 SQLite 和频道配置；恢复核对文件 SHA-256、数据库完整性和频道/记录计数。错误密钥、认证失败或缺失密钥不会创建新密钥假装恢复成功。恢复拒绝覆盖非空目录；即使 `--force` 也不能覆盖已有数据库。

备份密钥：`~/.config/social-dashboard/backup-key`（600），或 `SOCIAL_DASHBOARD_BACKUP_KEY` 指定路径。密钥必须独立保存安全离线副本；只有远端密文、没有密钥不能恢复。默认本机保留 7 份、R2 保留 30 份；远端删除只允许匹配加密备份路径。

生产切回恢复库前，先暂停采集/服务、保留现库及 WAL 的一致性备份，在空目录验证恢复结果，再切换运行目录。不能把数据库覆盖在仍运行的进程下；不能用旧 JSON 覆盖 SQLite。

## 7. 凭据与 YouTube 配额

- YouTube：`YOUTUBE_API_KEY` 或 `~/.config/social-dashboard/youtube-api-key`，公开数据不需要 Google OAuth。
- 采集及 R2：Worker secret `RUNNER_TOKEN` 和本机 `~/.config/social-dashboard/runner-token`（600）。Worker 内部发布仅允许规定公开路径。
- Git 配置：Worker secret `GH_TOKEN`；D1 保存私有密码和会话摘要。`users.json` 和 `web/users.json` 均已停止发布；Git 旧历史中的哈希不可撤回，必须换旧密码。
- 用量：本机持久 Cloudflare token 文件，Worker 部署需要独立 Workers/D1 权限；临时 wrangler OAuth 不应承担无人值守采集。

YouTube 默认 10,000 units/太平洋时间自然日，本机默认及硬上限 9000。请求发送前锁定并预留，失败也记账；当天 Google 配额耗尽、计数损坏或锁超时会停止 API。确认所有相关进程退出后才处理遗留锁，**不要删除当日计数/阻断文件**。顶栏仅显示本机预算，同项目其它客户端须在 Google Cloud 控制台核对。官方来源见 [youtube-api-quota-research.md](youtube-api-quota-research.md)。

## 8. 排障

| 现象 | 检查 |
|---|---|
| 无当前账号或要求登录 | 硬刷新；确认页面模块加载和 Worker `/auth/session`；失效会话重新登录 |
| 无频道 | admin 切全员；确认归属、R2 索引及当前频道分片，不再等待全量 93MB |
| 管理 403 | 首次换密要求、成员角色、最新 Git 归属；不能伪造 localStorage 绕过 |
| 新增一直排队 | 本机是否在线、cron 是否恢复、runner token 和远端请求接口 |
| 已采集但发布未完成 | 查看发布失败；重跑执行器恢复 collected/publishing，不重采已保存结果 |
| 频道列表未补全 | full 任务状态及配额；失效 API key、分页错误不能当成功 |
| 原始 JSON 修改不生效 | YouTube 运行时权威已切 SQLite，不能继续旧写入流程 |
| 上传失败或索引旧 | 必要分片/头像失败、发布锁、Worker R2 绑定；索引不会越过失败上传 |
| 备份无法解密 | 独立密钥文件、文件认证；不要重生成密钥覆盖原密钥 |
| Git 历史占用大 | 仅本机浅历史方案，先归档完整元数据；远端历史不得重写或强推 |

## 9. 本机 Git 浅历史与恢复

本机已切换为仅跟踪 `main` 的浅历史仓库，`.git` 从约 2.4GB 降至约 6.1MB。项目工作文件、SQLite、原始迁移输入和密钥未随 Git 元数据移动。远端仍保留原历史；此次只有正常提交与 push，没有重写历史或强推。

原始完整 `.git` 私有归档：

```text
~/.config/social-dashboard/social-dashboard-git-full-2026-10-02.tar.gz
SHA256 c96c29c37796771066d4a21ce70307417fea460e79809dd57b8c7450a6222f94
```

归档约 2.4GB、权限 600，包含原本机引用、reflog 和旧凭据哈希，禁止公开。它仍占本机磁盘，不能把项目元数据缩小量当成整机净释放量。

需要当前 `main` 的完整远端历史时，可在本机执行 `git fetch --unshallow origin main`；这不改远端，也不覆盖工作文件。原本机引用或 reflog 则从上述归档恢复：先暂停 watch/daily 与其它 Git 写入，在独立私有目录解包检查，不能直接覆盖正在使用的 `.git`。
